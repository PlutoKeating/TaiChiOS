# TaiChiOS 项目宪法

本文档记录 TaiChiOS 的长期产品原则。它约束系统默认行为与项目决策，但不剥夺经过身份确认、拥有相应权限的用户对自己系统作出明确选择的自由。

## 使命

TaiChiOS 致力于成为一个面向个人、团队与自治 Agent 的 AI 原生操作系统：它以最小可信基座组合能力，让意图能够转化为可理解、可审计、可预演、可执行和可回滚的系统行为。

## 原则

### 1. Linux 管理机器，Cordis 组合能力

TaiChiOS 是 Debian 衍生发行版。Linux 负责硬件、进程、内存、驱动和强制安全边界；Cordis 是用户态组合微内核，负责服务、插件、上下文与可逆生命周期。项目不以“自研硬件内核”作为目标。

### 2. 最小核心，最大扩展

模型、网络、界面、工具、存储、Agent 与大多数系统体验都应通过稳定能力接口替换。系统可以在纯字符、TUI、WebView、远程或 headless 形态间组合，不将任一具体界面或模型变成不可移除的产品前提。

### 3. 默认安全，主权优先

默认安装必须稳定、可理解且有护栏。与此同时，用户可以通过明确、经过身份验证的操作进入 Developer、Creator 或 YOLO 模式。系统必须真实说明风险，不得用暗门、诱导或模糊授权替代明确选择，也不得假借“安全”永久剥夺系统所有者的最终控制权。

在多用户环境中，自由以合法授权边界为前提：一个主体不能用自己的自由覆盖其他用户或组织所有者的权利。组织所有者可以授予或撤销系统级权限。

### 4. 模型中立

TaiChiOS 不绑定 DeepSeek 或任何特定模型。所有 LLM 能力通过系统级 Provider Registry 暴露标准接口；凭证由 Secret Service 管理。DeepSeek Harness 是首发系统插件集的重要组成，而不是系统身份的唯一来源。

### 5. 原生多用户与 Agent 身份

系统从第一天支持多个 Human User、Working Agent 与服务主体。Agent 可以作为用户拥有工作区、Session、任务、预算和授权，也可以由其他主体委托。所有重要行为均可归属到明确主体。

### 6. 自组织、自扩展与自演化

系统可以自主组合已安装能力；可以在策略允许时发现、评估和安装新能力；可以生成候选补丁与插件。自主性不被固定执行流程不必要地束缚，但所有持久改变都必须具备来源、影响、验证和恢复语义。

### 7. 改变应可预演、可验证、可回滚

插件安装、系统配置和升级应形成 Change Set，并支持 Dry Run。已提交改变必须产生清晰验证结果和 Rollback Point。即使主 Agent、主界面或普通插件树失效，独立恢复路径仍应可用。

### 8. 社区兼容，信任不外包

TaiChiOS 优先兼容 DSH 社区的 Bundle 与安装协议，使用 dsh-find、awesome-dsh-plugin 等生态发现能力。社区收录、Stars 和下载量只能帮助发现，不能代替签名、代码来源、权限评估与运行隔离。

### 9. 上游优先，补丁克制

Cordis、DeepSeek Harness、Debian 与界面插件作为明确上游依赖维护。只有无法通过插件、配置层或兼容适配器可靠实现的能力才进入上游核心补丁。每个补丁都必须说明退出策略。

### 10. 螺旋交付，脚手架先行

项目快速发布，但不以无结构的功能堆叠换取速度。每一轮先建立该范围的架构边界、契约、验证与恢复脚手架，再实现最小闭环，评估风险后进入下一圈。阶段产物应能被后续扩展，而不是注定废弃的一次性原型。

## 首发边界

- Debian 衍生、x86_64 首发。
- 交付 Live 启动介质和图形化安装器，支持安装到磁盘并配置 GRUB。
- dsh-TUI 是默认但可移除、可替换的 Shell 界面。
- WebView 是可选插件；headless 与纯字符模式是一等形态。
- 联网不是启动前提；网络能力应具备可插拔边界。
- 企业级 SLA、全盘加密、本地模型和桌面级 GUI 不进入最初硬性范围，但架构不得阻塞它们。

## 明确的非目标

- 不重写 Linux 内核、设备驱动或 Debian 包生态。
- 不建立只能使用 DeepSeek 模型的封闭系统。
- 不把逻辑 Context 隔离误称为安全沙箱。
- 不让单个 TUI、Web UI 或 Agent Loop 成为不可替换核心。
- 不以“AI 自主”为理由牺牲归责、恢复与用户知情权。
