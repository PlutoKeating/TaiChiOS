# TaiChiOS 0.1 MVP prerelease 4

This prerelease corrects the graphical-console handoff of the first public bootable, installable, runnable TaiChiOS image. It is intended for isolated x86_64 virtual machines, not production devices.

## Acceptance contract

The release workflow builds the binary ISO and corresponding-source ISO from this exact tag, then gates publication on:

- BIOS and UEFI Live boot without networking;
- a `taichi` user session actually attached to tty1 before `TAICHIOS_LIVE_SHELL_READY` is emitted;
- whole-disk installation under BIOS and UEFI;
- installed boot without the Live medium or networking, with `agetty` actually presenting the tty1 user login page before `TAICHIOS_INSTALLED_LOGIN_READY` is emitted;
- local hostname resolution, pinned Harness composition, and the independent Recovery target;
- package/source manifests, SHA-256 checksums, release metadata, build-environment recording, and GitHub build-provenance attestation.

Download `taichios-0.1-amd64.hybrid.iso` and verify it with `SHA256SUMS`. The Release also contains the corresponding-source ISO, source/package manifests, build environment, and machine-readable compatibility metadata.

## Console changes since mvp.3

- The serial console remains available for automated acceptance, while tty1 is the primary graphical console.
- Live boot now waits until the existing `taichi` autologin session is attached to tty1, leaving the user directly at a shell instead of a boot-log page.
- Installed boot does not autologin. It is accepted only when tty1 is actively presenting the user login page.
- Installer boots are excluded from the Live tty1 handoff, preventing a getty restart from racing the guarded whole-disk installer.
- The installer writes matching IPv4/IPv6 hostname entries so local `sudo` does not emit a hostname-resolution warning.

## Limitations

- Factory credentials remain development-only; production credential enrollment is not implemented.
- The default Provider is an offline mock. Production Provider and Secret Service enrollment are not implemented.
- Secure Boot and additional firmware remain disabled by the pinned image policy.
- Recovery supports the documented Profile-disable and managed-file rollback paths, not full-system cross-release rollback.
- This prerelease has no production security SLA. Report vulnerabilities through GitHub Security Advisories.
